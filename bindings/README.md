# Python bindings (rosetta to nanobind)

The bindings are generated by [rosetta](https://github.com/rosetta-bindings/rosetta) (MIT) with C++26 reflection. They are **committed expanded**: `generated/auto_nanobind.cpp` is plain nanobind with no reflection, so any C++20 compiler can build it, including MSVC.

## Build and test

```sh
pip install nanobind
cmake -S bindings -B build_py -DPython_EXECUTABLE=$(which python)
cmake --build build_py --config Release
python bindings/test_bindings.py build_py/Release      # or build_py on single-config generators
```

## What is bound (`manifest.json`)

| Kind | Items |
|---|---|
| Types | `CutterKind`, `P3`, `Tri`, `ProfileSeg`, `Cutter`, `TriMesh`, `Vec2`, `CLPoint`, `PathParams`, `ZMap`, `ZStats`, `StockMesh`, `ToolKind`, `Tool`, `ToolLibrary` |
| Kernels | `scallop_height`, `max_stepover`, `signed_distance_convex`, `kerf_path_convex`, `profile`, `validate_profile`, `profile_cutter`, `tapered_cutter`, `burr_cutter`, `disc_cutter`, `drop_triangle`, `drop_cutter`, `adaptive_line`, `zigzag` |
| Stock | `make_stock`, `cut_move`, `cut_passes`, `target_heights`, `deviation`, `zmap_mesh`, `mesh_volume`, `write_stl` |
| Tools | `tool_kind_name`, `tool_kind_from_name`, `all_tool_kinds`, `tool_kind_label`, `tool_kind_domain`, `tool_kind_envelope`, `tool_operation_names`, `wood_tool_library`, `validate_tool`, `has_cutter`, `cutter_of`, `disc_cutter_of`, `tool_operations`, `tools_for_operation`, `tools_of_kind`, `find_tool`, `holder_clearance`, `parse_tool_library`, `format_tool_library`, `read_tool_library`, `write_tool_library`, `stone_tool_library` |

C++ exceptions reach Python as `ValueError` (`std::invalid_argument`), `IndexError` (`std::out_of_range`) and `RuntimeError` (`std::runtime_error`).

Parameter names and docstrings come from the headers and the manifest. `generated/coverage.json` lists what was bound and what was skipped.

## Regenerate after an API change

Regeneration needs a reflection compiler, the Bloomberg clang-p2996 fork, on Linux or macOS (here: WSL Ubuntu 22.04). The fork's libc++ provides `<experimental/meta>`, so pass `-stdlib=libc++` and its include and lib paths:

```sh
rosetta_gen manifest.json gen
cmake -G Ninja -S gen -B /tmp/gen_build -DCMAKE_CXX_COMPILER=$P2996/bin/clang++ \
  "-DCMAKE_CXX_FLAGS=-stdlib=libc++ -isystem $P2996/include/c++/v1 -isystem $P2996/include/x86_64-unknown-linux-gnu/c++/v1" \
  "-DCMAKE_EXE_LINKER_FLAGS=-stdlib=libc++ -L$P2996/lib/x86_64-unknown-linux-gnu -Wl,-rpath,$P2996/lib/x86_64-unknown-linux-gnu -lc++abi"
cmake --build /tmp/gen_build
./generator out
cp out/nanobind/auto_nanobind.cpp out/api.json out/coverage.json generated/
```

Each generation writes `api.json`. `rosetta_gen --api-diff old new` reports API breaks between releases.
